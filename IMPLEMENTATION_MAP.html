Local OAuth CLI 애드온 구현 지도

이 문서는 로컬 OAuth CLI를 OpenAI·Anthropic 호환 API 표면과 native local CLI chat 표면으로 노출하는 설치형 프록시의 현재 구현 경계, 검증 기준, 남은 최적화 지점을 한눈에 정리합니다.

버전 0.2.0 · 단계 최신 코드 기준 벤치마크 재측정 (2026-06-22) · 상태 Direct + Proxy 완료 (paired)

현재 측정 현황: Direct·Proxy 모두 같은 견고한 표본으로 재측정을 마쳤습니다 — 속도 provider-parity n=10, semantic quality-realistic ×3, 이미지 image-realistic n=3 (OpenAI gpt-5.5 + Anthropic claude-opus-4-8). 핵심 결과: proxy-codex 속도 P/D 77~150%로 이전(200~272%) 대비 대폭 개선, proxy-claude tool 케이스는 direct보다 빠름(75~92%). 아래 "벤치마크 재측정 현황"이 현재 기준 paired 표이고, 이전(2026-06-04~06) 스냅샷은 git 이력에 있습니다.

최근 반영(커밋 33ee3dc~49bd9c2, MAP 미반영분 정리): Anthropic output_config + thinking parity(claude 런타임), client json_schema name/strict 보존(codex 런타임), 스트리밍 refusal/stop-metadata 정합, --extra-arg 대시 값 허용. 계약 회귀 게이트 contract-smoke 21/21, verify:runtime-boundary 통과.

주요 리스크: 이미지 reference_style_generation은 direct(gpt-5.5) 자체가 n=3 중 1회 87점으로 90 게이트 미달 — 단일 표본(n=1)이 가렸던 간헐 결함. 이미지 generator tail latency도 계속 추적 대상입니다.

현재 목표

프록시는 실제 provider API와 같은 입출력 표면을 보여야 하지만, 런타임에서는 direct provider API를 호출하지 않아야 합니다. direct API는 명시적인 비교 벤치마크, 기준 답변 생성, 품질 판정에만 사용합니다.

별도 /local/cli/sessions 표면은 provider-compatible 응답 재구성을 피하고, Codex app-server 또는 Claude stream-json session의 raw event를 작은 SSE envelope로 전달하는 native chat API입니다.

OpenAI provider-compatible text/tool과 Images API 표면의 기본 hot path는 codex-backend입니다. proxy-codex는 text/tool을 ChatGPT Codex backend SSE에 직접 매핑하고, Images API는 backend Responses image_generation tool의 image_generation_call.result를 OpenAI Images schema로 감쌉니다. native local chat은 Codex app-server를 유지합니다. access token은 만료 전 또는 인증 실패 후 refresh token으로 갱신하며, refresh token이 만료·폐기·재사용된 경우에만 재로그인을 요구합니다.

proxy-codex의 provider error policy, 이미지 벤치 계획, Claude 한국어 incident는 direct provider 기준 targeted closure에서 모두 95점 이상을 통과했습니다. 이미지 image2_via_gpt55는 full direct 비교에서 backend image_generation tool 결과가 없는 completion이 12건 재현됐고, 이후 backend-only no-image semantic retry와 transient fetch retry를 추가했습니다. 실패 12개 targeted closure에서는 no-image 실패가 0건으로 줄었습니다. 최신 타임라인 기준 이미지 속도 병목은 proxy wrapper나 tool 선택 전 단계가 아니라 Codex image generator 결과 대기입니다. Codex app-server native imageGeneration 경로도 같은 단일 케이스에서 64.5초로, backend Responses tool 61.4초보다 빠르지 않았습니다. request-shape probe 결과에 따라 backend tool field에는 action, output_format, output_compression을 직접 전달합니다. 색상 교체 edit 보존 규칙 보강 후 edit는 proxy/direct 모두 95점 이상으로 회복했습니다. flat/vector reference-style은 edge-preserving PNG flat postprocess 적용 후 proxy 최저 96점으로 통과했고, 같은 run의 direct는 최저 89점으로 실패했습니다. 이미지 runtime transform PoC에서는 JPEG photoreal은 canonical 생성 후 runtime 변환이 47.1% 시간으로 빨랐지만, flat WebP는 158.9%로 느려 format/style별 capability rule이 필요합니다. 분류별 5회 format discovery에서는 textOrLogoGraphic WebP, photorealRaster WebP/PNG/default, productIdentity PNG/WebP/default가 통과했고, referenceOrEdit와 unknownHybrid는 포맷보다 품질 안정화가 먼저입니다. 추가 targeted discovery에서는 simpleFlatGraphic이 prompt 다양화 후 모든 포맷에서 min 95 미만이라 rule 승격을 보류했고, photorealRaster는 WebP가 가장 균형적인 후보입니다. 프롬프트만으로 format/geometry route를 안정적으로 판정하기 어려운 케이스를 위해 proxy-only x_proxy_image_route 확장 필드를 추가했고, 이 필드는 provider parity가 아닌 proxy enhanced 벤치 행으로 분리합니다.

런타임 흐름

1. API 수신 startLocalApiProxy가 OpenAI Chat, OpenAI Responses, OpenAI Images, Anthropic Messages 호환 요청을 받습니다.
2. 요청 정규화 provider별 입력을 내부 메시지, 도구, 이미지 참조, 응답 형식, 스트리밍 모드, effort, verbosity로 변환합니다.
3. 로컬 CLI 실행 OpenAI text/tool과 Images API 표면은 기본적으로 CodexBackendTransport, native chat은 CodexAppServerBackend, Anthropic 표면은 ClaudeCodeBackend로 보냅니다.
4. 응답 재구성 텍스트, 도구 호출, SSE delta, provider token usage, 이미지 응답을 원래 API 스키마에 맞춰 반환합니다.
5. Native chat /local/cli/sessions는 provider 응답으로 재구성하지 않고 raw CLI event를 cli.event SSE envelope로 전달합니다.

OpenAI 텍스트·도구 속도 proxy-codex(제품 hot path는 codex-backend)는 n=10 재측정에서 direct 대비 P/D 77~150%로 이전(200~272%)보다 크게 개선됐습니다. chat 텍스트는 77%로 direct보다 빠르고, responses 텍스트·스트리밍은 ~100%로 동률이며, 도구 스트리밍/결과(131~150%)가 가장 느린 축입니다. release-gate는 proxy-codex를 제품 대표값으로 봅니다. proxy-codex-backend는 text/tool hot path 진단값(B/D 77~167%), proxy-codex-app-server는 app-server turnWaitMs 원인 분석값으로 사용합니다.
