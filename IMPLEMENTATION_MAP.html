ggui OAuth CLI Add-on Implementation Map

Current map for the local OAuth CLI API adapter, focused on runtime proxy behavior and benchmark-sensitive contracts.

Runtime Flow

1. HTTP API startLocalApiProxy accepts OpenAI Chat, OpenAI Responses, OpenAI Images generation, and Anthropic Messages compatible requests.
2. Normalize Provider-shaped input is normalized into internal messages, tools, image references, image-generation fallback requests, schema mode, and stream mode.
3. Local CLI Backend Requests route to CodexAppServerBackend or ClaudeCodeBackend using local OAuth CLI auth.
4. Provider Shape Text, tool calls, streaming deltas, and provider token usage are mapped back to exact API-compatible responses.

Codex Proxy Context Isolation

Concern Current Authority Reason Verification
User prompt preservation buildPrompt(request) remains the request payload authority. The optimization removes ambient CLI context only; it does not summarize, rewrite, or shrink API input. Schema/output parity tests and live benchmark completions pass.
Codex auth createCodexIsolation() copies only auth.json into an ephemeral CODEX_HOME. Local OAuth auth is preserved while user MCP, plugins, hooks, projects, memory, and history stay out of the proxy run. Unit test asserts auth copy and config exclusion.
Ambient tool context DISABLED_CODEX_CONTEXT_FEATURES disables apps, plugins, browser/computer tools, shell tool, multi-agent, hooks, goals, workspace dependencies, and Codex web search. These features are useful in Codex sessions but inflate model-visible API proxy context. Input tokens dropped from about 14k to about 1.9-2.0k in proxy-codex text/tool cases.
Workspace context Each Codex thread and turn uses an ephemeral temp workspace as cwd and runtimeWorkspaceRoots. API completion requests should not read repository files or project instructions unless the API payload includes them. AGENTS/project context no longer drives the proxy-codex token count.

Claude Structured Fast Path

Concern Current Authority Reason Verification
Structured non-image requests ClaudeCodeBackend now routes non-image JSON/tool requests through the persistent stream-json session. This avoids per-request Claude process startup and expensive --json-schema structured-output validation for hot proxy paths. OpenAI Chat tool_call dropped from 8174ms to 1955ms in the latest quality-gated benchmark.
Image requests Image-bearing requests stay on the one-shot stream-json path. Image payload setup and file cleanup remain isolated from the long-lived text session. Real multimodal benchmark passed 9/9 after switching the benchmark fixture to a provider-accepted generated 64x64 red PNG.
Quality gate Semantic quality benchmark uses provider-paired direct API references: proxy-codex compares with OpenAI API, proxy-claude with Anthropic API. Context or schema enforcement changes can improve speed while subtly changing answer quality, and API-surface matching is not the same as backend-provider quality matching. The judge treats direct provider output as a semantic reference, not a strict style template. Latest realistic semantic suite passed 24/24 with proxy semantic scores from 96 to 100 at a 95-point gate; latest non-multimodal schema run passed 54/54.

Image Generation Fallback

Concern Current Authority Reason Verification
image-2 Images API requests /v1/images/generations, /v1/images/edits, and /v1/images/variations normalize Images API input, then call OpenAI Responses with gpt-5.5, the built-in image_generation tool, and a quality-derived reasoning effort (high/default -> xhigh, medium -> high, low -> medium). Direct probing showed gpt-5.5 is rejected by the Images endpoint but succeeds through Responses image_generation, so the proxy preserves the caller-facing Images shape while using the viable provider path. Expanded opt-in image benchmark passed 7/7; detail-focused follow-up passed 5/5 for API fields, multipart edit streaming, and multipart variation, alongside the 2/2 stream dedupe rerun.
Returned image shape Proxy responses return created, exactly one of data[].b64_json or data[].url, optional metadata, and Images-compatible SSE events for streamed partial/final images. GPT image outputs are base64 images; URL responses are served from a local in-memory generated-image store with a bounded TTL. Optional response metadata is emitted only when the proxy can derive it from request/result state. Contract tests cover request routing, URL fetchback, streaming partial/final events, JSON edit image references, multipart image[] uploads, multipart-only variations, option validation, metadata preservation, and multi-image n.

Tool Result Continuation

Concern Current Authority Reason Verification
Auto tool result turns backend-contract disables the proxy tool-decision schema only when tool_choice is auto and the latest normalized message is a provider tool result. This matches the next step of the provider tool loop: after a tool result, the assistant normally produces a final message instead of another tool-decision envelope. OpenAI Chat tool_result improved from 2465ms to 2003ms on proxy-codex and from 3496ms to 1514ms on proxy-claude.
Forced tool calls required and named tool choices still use the tool-decision schema. Those requests explicitly ask the provider to choose or call tools, so the proxy still needs structured tool-call extraction. Contract tests cover auto-before-tool, required-after-result, final-answer mode, and JSON-schema preservation.
Benchmark variance api-comparison-benchmark supports --suite, --targets, and --cases filters with exact, substring, and wildcard matching. Single-sample latency gates can fail on Codex provider outliers unrelated to a changed branch, so outlier cases need targeted repeated medians, while suite presets prevent accidental case omissions. Rows now include outlier tags; proxy-codex outliers also identify the dominant backend phase when timing is available.
API benchmark design docs/api-benchmark-design.md defines contract, provider parity, semantic quality, image quality, latency, and release-gate suites. Quality checks must compare against the right direct provider authority and must use diverse real-use prompts and fixtures instead of a single friendly smoke case. Benchmark implementation now includes suite presets, 10 semantic prompt shapes, direct Images positive/negative rows, image error parity rows, red/blue multi-image rows, and vision-based imageQuality gates; the lightweight real Images negative probe passed 7/7.
Codex JSON schema latency No prompt-only schema or idle-thread prewarm fast path is active. Both probes preserved schema exactness and semantic quality, but neither improved median latency over the structured-output baseline. Baseline median 2088ms; prompt-only schema 2465ms; idle-thread prewarm 2605ms. Keep the structured schema path.
Compact Codex proxy context Codex proxy threads and turns force personality: none, model_reasoning_summary: none, web_search: disabled, and shorter API-wrapper instructions. This preserves the user prompt while removing proxy-added conversational context that direct provider APIs do not need. Representative benchmark passed 14/14; semantic quality stayed 98-99; representative Codex input is now about 1.9-2.0k tokens.
Codex context floor probe Direct app-server probes compared the product payload, no wrapper, base-only wrapper, and shorter wrapper variants. The current wrapper is needed to suppress default Codex instructions; omitting it increased input from about 4.6k to 8.7k tokens. A more aggressive shorter wrapper saved only about 33 tokens and weakens response guardrails, so it is not active.
Codex usage-tail timing The Codex waiter now resolves immediately when provider token usage arrives after turn/completed, while keeping the 100ms fallback only for missing usage. This preserves exact provider usage and removes a deterministic tail in reversed notification order without changing API response schemas. Fake app-server test proves the tail removal. Real Codex timing probes show usageWaitMs=0; current latency is dominated by provider turnWaitMs.
Benchmark phase diagnostics api-comparison-benchmark records proxy-codex-only backendTiming summaries outside the public API response. Contract exactness stays intact while benchmarks can separate local overhead from provider turn latency. Six-case streaming probe passed 6/6; outliers were dominated by turnWaitMs, usually with 0.89-1.00 turn-wait share.
Codex partial streaming CodexAppServerBackend buffers text, completion, and provider-usage notifications that arrive before a turn waiter exists. App-server can emit item/agentMessage/delta before turn/completed; buffering prevents early deltas from being lost if they race ahead of turn/start response handling. Fake app-server race tests pass. Real protocol probe found rawResponseItem/completed is not earlier than text deltas, so experimentalRawEvents remains off.
Streaming first-latency comparison Streaming benchmark now compares first text/tool-argument latency against direct OpenAI and Anthropic APIs; image stream rows also expose firstImageMs. Public API schema stays exact while the benchmark separates first SSE data, first text, first tool argument/image payload, total latency, and proxy-codex backend phases. The targeted paired image-2 stream diagnostic passed 1/1 rows over 3 repeats before quota exhaustion. Proxy firstImageMs median was 9.620s versus direct Responses 13.741s, while total latency was 17.012s versus 14.274s. A later 10-repeat run reached provider insufficient_quota; stream errors now preserve provider fields and paired diagnostics retain sampleFailures.
Codex reasoning effort Proxy-Codex reads request-level effort from OpenAI Chat reasoning_effort and Responses reasoning.effort. The API request is the authority; CLI --reasoning-effort is an explicit override, and settings.json codexProxy.fallbackReasoningEffort is the fallback when both are omitted. Supported efforts none, low, medium, high, and xhigh each passed 20/20 across four runs. settings.json currently selects medium. Current direct gpt-5.5 rejects minimal; negative parity benchmark passed 4/4 with matching 400 invalid-request shapes.
