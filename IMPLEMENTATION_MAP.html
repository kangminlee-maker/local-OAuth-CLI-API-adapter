Local OAuth CLI 애드온 구현 지도

이 문서는 로컬 OAuth CLI를 OpenAI·Anthropic 호환 API 표면과 native local CLI chat 표면으로 노출하는 설치형 프록시의 현재 구현 경계, 검증 기준, 남은 최적화 지점을 한눈에 정리합니다.

현재 목표

프록시는 실제 provider API와 같은 입출력 표면을 보여야 하지만, 런타임에서는 direct provider API를 호출하지 않아야 합니다. direct API는 명시적인 비교 벤치마크, 기준 답변 생성, 품질 판정에만 사용합니다.

별도 /local/cli/sessions 표면은 provider-compatible 응답 재구성을 피하고, Codex app-server 또는 Claude stream-json session의 raw event를 작은 SSE envelope로 전달하는 native chat API입니다.

OpenAI provider-compatible text/tool과 Images API 표면의 기본 hot path는 codex-backend입니다. proxy-codex는 text/tool을 ChatGPT Codex backend SSE에 직접 매핑하고, Images API는 backend Responses image_generation tool의 image_generation_call.result를 OpenAI Images schema로 감쌉니다. native local chat은 Codex app-server를 유지합니다. access token은 만료 전 또는 인증 실패 후 refresh token으로 갱신하며, refresh token이 만료·폐기·재사용된 경우에만 재로그인을 요구합니다.

proxy-codex의 provider error policy, 이미지 벤치 계획, Claude 한국어 incident는 direct provider 기준 targeted closure에서 모두 95점 이상을 통과했습니다. 이미지 image2_via_gpt55는 full direct 비교에서 backend image_generation tool 결과가 없는 completion이 12건 재현됐고, 이후 backend-only no-image semantic retry와 transient fetch retry를 추가했습니다. 실패 12개 targeted closure에서는 no-image 실패가 0건으로 줄었습니다. 최신 타임라인 기준 이미지 속도 병목은 proxy wrapper나 tool 선택 전 단계가 아니라 Codex image generator 결과 대기입니다. Codex app-server native imageGeneration 경로도 같은 단일 케이스에서 64.5초로, backend Responses tool 61.4초보다 빠르지 않았습니다. request-shape probe 결과에 따라 backend tool field에는 action, output_format, output_compression을 직접 전달합니다. 색상 교체 edit 보존 규칙 보강 후 edit는 proxy/direct 모두 95점 이상으로 회복했습니다. flat/vector reference-style은 edge-preserving PNG flat postprocess 적용 후 proxy 최저 96점으로 통과했고, 같은 run의 direct는 최저 89점으로 실패했습니다.

런타임 흐름

1. API 수신 startLocalApiProxy가 OpenAI Chat, OpenAI Responses, OpenAI Images, Anthropic Messages 호환 요청을 받습니다.
2. 요청 정규화 provider별 입력을 내부 메시지, 도구, 이미지 참조, 응답 형식, 스트리밍 모드, effort, verbosity로 변환합니다.
3. 로컬 CLI 실행 OpenAI text/tool과 Images API 표면은 기본적으로 CodexBackendTransport, native chat은 CodexAppServerBackend, Anthropic 표면은 ClaudeCodeBackend로 보냅니다.
4. 응답 재구성 텍스트, 도구 호출, SSE delta, provider token usage, 이미지 응답을 원래 API 스키마에 맞춰 반환합니다.
5. Native chat /local/cli/sessions는 provider 응답으로 재구성하지 않고 raw CLI event를 cli.event SSE envelope로 전달합니다.

벤치마크 읽는 법

아래 통합 표는 현재 기준으로 direct와 proxy가 같은 suite에서 함께 측정된 속도·품질 행 전체를 Direct, Proxy, Codex Backend, Proxy/Direct * 100 (%), Backend/Direct * 100 (%) 형태로 정리한 것입니다.

속도 행은 낮을수록 좋으므로 100% 초과는 proxy가 direct보다 느리다는 뜻입니다. 품질 행은 높을수록 좋으므로 100%에 가까울수록 direct 기준에 가까우며, 95점 미만은 현재 품질 게이트 미달입니다.

계약 오류 응답처럼 품질이나 체감 속도 판단이 아닌 스키마 호환성 행은 이 표에서 제외하고 근거 artifact에만 남겼습니다.

벤치마크 해석

영역 현재 판단 다음 의미
OpenAI 텍스트·도구 속도 proxy-codex는 이제 하이브리드 제품 target입니다. 최신 smoke 기준 text/tool은 codex-backend hot path를 타며, Chat 도구 argument는 2,496ms에서 1,683ms, Responses 도구 argument는 2,652ms에서 1,713ms로 줄었습니다. release-gate는 proxy-codex를 제품 대표값으로 봅니다. proxy-codex-backend는 text/tool hot path 진단값, proxy-codex-app-server는 app-server turnWaitMs 원인 분석과 회귀 비교값으로 사용합니다.
Anthropic 텍스트·도구 속도 proxy-claude는 direct Opus 대비 대체로 1.1배에서 2.3배 느립니다. 중앙값은 OpenAI proxy보다 안정적이지만, 멀티모달과 스트리밍 꼬리 지연을 계속 분리 계측해야 합니다.
의미 품질 provider-paired targeted closure 기준 provider error policy, 이미지 벤치 계획, Claude 한국어 incident는 모두 95점 이상입니다. 이제 남은 확인은 전체 realistic semantic suite 3회 반복 안정성입니다. 단일 targeted closure는 닫혔지만 stochastic 품질 흔들림이 있었으므로 반복 게이트로 확인해야 합니다.
이미지 품질 no-image retry 후 성공한 targeted image 행 대부분은 95점 이상입니다. 최신 2회 재측정에서 API fields/WebP는 proxy 최저 97점, edit 색상 교체는 proxy 최저 96점으로 통과했습니다. reference style은 edge-preserving flat postprocess 적용 후 proxy 최저 96점으로 통과했고, 같은 run의 direct는 최저 89점으로 실패했습니다. 다음 품질 작업은 reference-style 후처리의 일반화 검증입니다. 8색 강제는 blue/coral 의미 색상과 edge를 망쳐 68-70점까지 떨어졌고, 최종 방식은 edge를 보존하며 내부/배경 gradient만 줄입니다.
이미지 속도 no-image retry는 실패율을 낮췄지만 tail latency를 크게 늘렸습니다. 최신 reference-style paired run에서 proxy는 61.9초/71.0초, direct는 67.1초/61.8초로 비슷한 수준이었고, API fields/WebP proxy는 48.2초/73.4초로 여전히 흔들립니다. edit 색상 교체는 proxy 19.5초, direct 18.9초로 direct에 근접했습니다. Codex backend는 0.6-0.8초에 SSE를 시작하고 1.2-1.4초에 image item을 추가하며 약 3초에 generating에 들어갑니다. 이후 첫 이미지 결과까지의 generator 대기가 tail을 결정합니다. 품질 문제는 줄었으므로 다음 속도 개선은 backend generator tail 회피, 요청 shape 안정화, 또는 병렬/재시도 정책 조정에서 찾아야 합니다.

Codex backend 이미지 타임라인

현재 기본 이미지 경로는 codex-backend입니다. 아래 표는 proxy HTTP wrapper가 아니라 backend SSE 내부 이벤트 기준으로, 요청 시작부터 image item 선택, generating, 첫 이미지 결과까지를 분리한 최신 root-cause 측정입니다.
