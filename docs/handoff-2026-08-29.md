## 2. 확정된 원칙 — 재논의 금지

**어댑터는 CLI의 인터페이스를 API와 같게 만드는 도구다.** 같은 모델이라도 CLI와 API는 인터페이스가
달라 응답 특성이 달라지고, 그 차이를 없애는 것이 어댑터의 존재 이유다. 다만 그 일은 이렇게 한다:

1. **환경 제약** — 그 동작이 애초에 불가능하게 (자식의 HOME·cwd·설정 소스·MCP)
2. **런타임 노브** — 네이티브 플래그·파라미터로 끄기
3. **상쇄 래퍼** — 끌 수 없으면 **응답 경로에서 코드가** 잔재를 제거
4. ~~프롬프트 주입~~ — **금지**

어댑터의 일은 두 방향이다: **빼기**(CLI 래퍼 벗겨내기·우회)와 **더하기**(API에만 있는 기능 구현).
더하기의 올바른 형태는 **제약은 런타임 노브가 걸고, 번역은 프록시 코드가 한다**.

### 옵션 구현 규칙 (2026-08-29 확정)

**옵션은 약속이고 프롬프트는 부탁이다.** 약속을 부탁으로 구현하면 어댑터가 클라이언트에게 거짓말을 한다.

| 상황 | 해야 할 것 |
|---|---|
| 슬롯이 있다 | 슬롯으로 보낸다. 산문 금지 |
| 슬롯이 없고 코드로 검증 가능 | 코드로 구현 (`n`이 이미 그렇다 — 병렬 턴) |
| 슬롯도 없고 검증도 안 된다 | **거절하거나 미지원으로 문서화.** 부탁으로 구현하지 않는다 |
| 호출자가 요청하지 않았다 | **넣지 않는다** |

**절대 하지 말 것: 수용해놓고 전달하지 않으면서 응답에는 적용됐다고 에코하는 것.**

### 판정 기준 (2026-08-29 확정)

- **분량은 판정 축이 아니다.** 모델은 비결정적이고, A/A 대조에서 vendor 자신의 run 간 변동이
  중앙값 13.4%(최대 30%)로 관측 격차와 같은 크기였다. 판정은 **형식과 내용 품질**로 하고, 분량은
  그 둘이 통과한 뒤에도 크고 일관된 차이가 남을 때만 조사 단서로 쓴다.
- 검증 권위는 손으로 쓴 문항이 아니라 **API 표면 자체**다. 설계는
  `docs/conformance-suite-design.md`, 원자료는 `docs/conformance-matrix.md`(148행).
- LLM 판정은 게이트에서 내려왔다. 그것이 런타임을 문항에 맞춰 조정되게 만든 유인이었다.

## 3. 바로 다음 작업 — 이미지 2단계

`src/proxy/image2-via-gpt55.ts`의 산문 주입을 위 규칙으로 정리한다. 1단계(중복 4건)는 끝났다.

**2단계 범위(위 규칙 확정으로 넓어졌다):**

1. **슬롯 배선 4건** — `background`, `moderation`, `input_fidelity`, `mask`(= `input_image_mask`).
   네 슬롯 모두 라이브 Codex 백엔드 스키마에 **존재한다**(2026-08-29 리서치로 확인, 이전 감사의
   "슬롯 없음"은 오판이었다). 지금은 안 보내고 산문으로만 말한다.
2. **거짓 에코 제거** — `codex-backend-transport.ts:893`·`699`·`716`이 `background`를 응답에
   되돌려 준다. 도구에는 안 보내면서. `defaults-diff`가 찾은 `temperature` 거짓 에코도 같은 부류다.
3. **미지원 선언** — 슬롯도 검증도 없는 것(`style`, negative prompt 개념 자체)은 배선이 아니라
   거절 또는 미지원 문서화.

배선 뒤 해당 산문을 지운다. 부수 효과로 `gpt-image-2` 요청의 `background: transparent`가
**수용 후 조용히 폐기**되던 것이 고쳐진다.

**3단계(그 다음)** — regex 계열 5개 제거: `geometryConstraints`,
`targetedEditPreservationConstraints`, `flatGraphicConstraints`, `negativePromptConstraints`,
`editConstraints`의 일반 절반. 전부 **호출자 프롬프트를 정규식으로 읽어** 발동하고 API 필드가 없으며
이미지 벤치 문장(`A simple flat red square centered on a white background. No text.`)에 걸린다.
주의: `flatGraphicConstraints`는 코드 쪽 후처리(`flat-image-postprocess.ts`)도 같은 술어
(`asksForFlatGraphicPrompt`)로 게이트하므로 산문만 지우면 안 된다.

현재 주입량(실측): 평범한 요청 **1줄/219자** vs 벤치 문장 **12줄/1,630자**, 벤치 편집 **13줄/1,925자**.

## 5. 이 세션에서 반복해서 값을 한 규율

이게 가장 중요하다. 오늘 잡은 결함의 상당수가 **내 수정이 만든 것**이었고, 전부 같은 부류였다:
**아무것도 아닌 것과 비교해서 통과하는 검사.**

- **모든 게이트를 변이로 양방향 확인한다.** "고쳤다" 뒤에 반드시 되돌려서 빨간불을 본다.
  오늘 이걸로 잡은 것: 판정 역전, 잘못 겨눈 단언(추출기를 비워도 초록), 빠뜨린 return.
- **기대와 일치하는 관찰이 계기를 의심할 때다.** 프로브가 `timeout` 부재로 실행조차 안 됐는데
  파이프의 grep 종료 코드를 보고 성공으로 읽은 일, 실패 행 패턴이 안 맞아 "FAIL 0"으로 보고한 일이
  각각 있었다.
- **파이프 종료 코드는 마지막 단계 것이다.** 테스트 대상의 상태를 직접 받아라.
- **`pgrep -f`는 자기 자신을 매칭한다.** 프로세스 판정은 PID로.
- **대조군을 둔다.** 재현 하네스에 "정상 케이스"를 함께 넣지 않으면 하네스 고장과 결함을 구분 못 한다.
  오늘 P0 재현 하네스는 두 번 틀렸다(백엔드 인터페이스 오류로 호출조차 안 됨, 노멀라이저 층만 봄).
- **리뷰 지적을 그대로 받지 않는다.** 세 라운드 21건 중 일부는 이미 고쳐진 상태를 본 것이었고, 일부는
  판정이 절반만 맞았다. 코드에서 재확인한 뒤에 고친다.
- **macOS에 `timeout`이 없다.** 도구 자체 타임아웃을 쓴다.
