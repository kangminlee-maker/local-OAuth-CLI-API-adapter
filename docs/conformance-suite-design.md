# 적합성 스위트 설계

이 문서는 어댑터가 무엇을 만족해야 하는지, 그리고 그것을 어떻게 판정하는지를 정의한다.
`docs/api-benchmark-design.md`가 정의하던 semantic quality 게이트를 **대체**한다. 그 문서는
이행이 끝날 때까지 latency·image·실행 명령의 권위로 남는다(§7).

## 0. 왜 다시 쓰는가

어댑터의 일은 CLI로 감싸인 모델을 API처럼 **동작하게** 만드는 것이다. 같은 모델이라도 CLI와
API는 인터페이스가 달라 응답 특성이 달라지고, 그 차이를 없애는 것이 어댑터의 존재 이유다.
그 일은 **코드·런타임 플래그·환경 제약**으로 해야 하며, 호출자의 입력에 더하거나 빼거나
고쳐 쓰는 방식으로 해서는 안 된다. CLI 래퍼의 일부를 벗겨내거나 우회하고, API에만 있는 기능을
구현해 붙이고, 끌 수 없는 기능은 응답 경로에서 상쇄한다 — 그 셋이 정당한 메커니즘이다.

이전 스위트는 이 일을 판정하지 못했다. 78개 케이스 중 40개가 손으로 쓴 10개 질문을 네 표면에
복제한 것이었고, 런타임은 그 질문들에 맞춰 조정됐다. 프록시 안에 산문 지시문 46줄이 쌓였고,
그 46줄 전부가 **같은 커밋에서 그 질문 정의나 judge 루브릭을 함께 고친** 커밋에서 들어왔다
(계보 조사 2026-08-28). 스위트가 측정이 아니라 표적이 됐다.

같은 조사에서 드러난 구조적 결함들:

- 저장된 아티팩트에 **vendor 응답 원본이 없다**. 판정 결과와 텍스트 표본만 남긴다. 그 결과
  이 프로젝트 역사에서 vendor 요청 필드 기본값을 **한 번도 관찰한 적이 없다**.
- Anthropic direct 행은 같은 케이스가 아카이브 전반에서 `ok:true`와 `ok:false`를 오간다.
  그 초록은 증거가 아니다.
- 계약이 지원한다고 선언한 표면 하나(`GET /v1/models`)에 케이스가 0건이다. vendor가
  문서화한 엔드포인트 하나(`/v1/messages/count_tokens`)에 우리는 404를 준다.
- Responses 스트림 형태 단언이 이벤트 이름과 순서는 보지만 **종결자를 보지 않는다**.

## 1. 단위 — claim

원자 단위는 **claim**이다: 관찰 가능한 동작 하나에 대한 반증 가능한 진술 하나.

식별자는 `surface × operation × subject × facet`.

```text
messages.create × stream × omitted-default
responses.create × max_output_tokens × invalid-value
chat.completions.create × protocol × stream-terminator
messages.create × prompt-content × preservation
```

적합성 매트릭스의 **행은 원자적이지 않다** — 한 행이 값 공간·생략 시 동작·잘못된 값의 거동·
응답에 미치는 효과·구현 여부를 함께 싣는다. 러너가 행을 claim으로 전개한다. 라우트 인벤토리와
프로토콜 인벤토리가 엔드포인트·응답 형태·스트림 수명주기·프롬프트 보존 claim을 추가한다.

claim 하나가 요청 하나가 아닐 수 있다. 생략 시 기본값 claim은 **생략·명시 후보·대조** 세
요청이 필요하다. 호출은 중복 제거하되 결과는 claim 단위로 보고한다.

프롬프트와 요청 본문은 claim의 **정체가 아니라 실현**이다. 버전이 붙은 템플릿에서 실행별
시드로 생성한다. 고정 질문에 맞춘 조정은 회전하는 내용과 홀드아웃 계열에서 살아남지 못한다.

### 프롬프트 보존 claim

원칙을 규칙이 아니라 **게이트**로 만드는 claim이다. 호출자가 보낸 각 span에 카나리를 심고,
CLI 경계에서 프롬프트를 담은 내용을 재구성해 **모든 호출자 span이 정확히 한 번, 원래 순서로,
추가된 의미 span 없이** 나타남을 증명한다. 전송을 위한 프레이밍은 닫힌 비산문 allowlist에서만
허용한다.

## 2. 권위와 형식

버전이 붙은 기계 판독 매니페스트(`spec/conformance.yaml`) 하나가 호환성 계약이고, 내용 주소로
고정된 캡처 번들이 그 증거다.

계약에 **데이터로** 들어가는 것: 표면·오퍼레이션·요청 필드 경로·facet, vendor 값 공간과 관찰
가능한 동작, 생략 시 기대 동작, 잘못된 값의 거동, 증거 참조(문서 리비전 또는 캡처 다이제스트),
호환성 처분(vendor와 일치 / 문서화된 발산 / 공표 범위 밖), 프로브 파라미터와 matcher 선택.

**"프록시가 이걸 구현한다"는 편집 가능한 데이터로 두지 않는다.** 계약에는 *주장된* 지원만 담고,
실제 구현 상태는 claim을 실행해 도출한다. 증거 등급과 안정성도 마찬가지로 증거 참조와 관찰에서
계산하며 손으로 유지하는 라벨이 아니다.

**원본 캡처는 증거이지 자동으로 계약이 아니다.** 새 vendor 캡처는 후보 관찰이 되고, 계약으로의
승격은 명시적 심의를 거친다. vendor 드리프트가 기대 동작을 조용히 다시 쓰게 두지 않는다.

코드가 소유하는 것: 매니페스트 스키마 검증과 claim 전개, 프로브 생성과 호출 중복 제거, 캡처·
비밀 제거·파싱·직렬화, matcher와 통계 계산, 요청→CLI 프롬프트 span 재구성, 게이트 분류와 보고서
생성.

러너·생성 문서·커버리지 보고서·프로브 계획은 **같은 매니페스트를 읽는다**. 테스트 코드가 기대
vendor 값을 따로 갖지 않는다. 계약 값을 지우거나 바꾸면 모든 투영과 단언이 함께 바뀌어야 한다.

## 3. 실행 모델 — 세 레인

같은 claim 전개에서 파생된다.

| 레인 | 무엇을 실행하는가 | 케이던스·권위 |
|---|---|---|
| **저장 캡처** | vendor 원본 파싱, CLI 스트림 원본을 실제 응답 보정 코드로 재생, SDK 디코딩, matcher, 실패 경로 | 매 커밋. **결정적 주 게이트** |
| **프록시 단독** | 표준 SDK → 프록시, 라우트 커버리지, 요청 매핑, 기록 CLI, **프롬프트 보존**, 런타임 플래그·환경, 스트림 종결 | 기록 CLI는 매 커밋, 실제 CLI E2E는 야간·릴리스 전 |
| **라이브 vendor** | 생략 시 기본값, 허용 값, 잘못된 값의 에러, 헤더, 스트리밍 원본 거동, vendor 드리프트, 페어 품질 시행 | 저렴 티어(10 프로브/12 호출) 야간, 전체 티어(37/53) 주간·릴리스 전·모델 변경 시 |

**기록 CLI**가 프롬프트 변조에 대한 하드 게이트다. argv·stdin·환경 allowlist·구성된 요청을
캡처하고 저장된 CLI 응답을 정상 런타임으로 돌려준다. vendor 비용이 들지 않으므로 매 커밋에서
돈다. 실제 CLI 레인은 이 기록 실현이 프로덕션 경로를 대체하지 않았음을 증명하지만, 확률적인
답변 내용은 요청 단위 게이트가 아니다.

**PR은 vendor API 호출을 하지 않는다.** vendor 호출 예산은 실행 전에 고정한다.

불안정한 필드는 모든 시도를 보존하고 분포로 비교한다. direct 초록 한 번이 불안정한 claim을
승격시키지 않는다. 생략 시 기본값은 **대조가 뒷받침할 때만** 관찰됨이 된다 — 생략과 명시 후보가
일치하고 의미 있는 대안이 다를 때. 응답이 후보를 구분하지 못하면 기본값은 미상으로 남는다.

## 4. 아티팩트

실행마다 내용 주소로 고정된 불변 번들을 쓴다. **"원본"은 SDK 디코딩이나 스위트 정규화 이전의
바이트**를 뜻한다. 인증 자료는 캡처 경계에서 제외하고 "존재함, 제거됨"으로만 표시한다.

저장한다: 매니페스트 스냅샷·스키마 다이제스트·러너 버전·프록시 커밋·dirty 여부·claim 전개 /
SDK 입력과 버전 / HTTP 메서드·경로·쿼리·비밀 아닌 헤더·**요청 본문 원본 바이트**(필드가 생략됐음을
증명하는 유일한 방법) / vendor 상태·응답 헤더·응답 본문 원본 바이트 / 스트림의 와이어 바이트·
청크 경계·수신 타임스탬프·파싱된 이벤트 경계·**종결 이벤트 또는 센티널**·EOF 관찰 / 프록시 응답의
같은 항목 / CLI 실행 파일 경로와 다이제스트·버전·argv·작업 디렉터리·허용된 환경 값·stdin·stdout·
stderr·종료 상태·타이밍 / **재시도는 시도마다 별개 기록**(실패한 시도를 성공으로 덮지 않는다) /
표준 SDK가 디코딩한 객체와 예외 / claim 결과와 그것을 뒷받침하는 JSON 경로 또는 바이트 오프셋 /
provider·모델 식별자·핑거프린트·런타임 버전·켜진 프록시 플래그 / claim → 프로브 그룹 → 요청 →
vendor 캡처 → CLI 캡처 → 보정된 프록시 응답 → matcher 버전의 계보.

파싱된 JSON·정규화된 응답·보고서·점수는 **버릴 수 있는 투영**이다. 이름 붙은 파서 버전으로
원본에서 재생 가능해야 하고, 파서가 바뀌어도 이력이 다시 쓰이지 않도록 원래 투영과 재파싱을
함께 보관한다.

이전 스위트의 실패가 여기 있었다: **결론을 저장하고 증거를 저장하지 않았다.** 규칙은 —
결론을 다시 도출하는 데 필요한 것을 저장한다.

## 5. 품질 축 — 셋으로 나눈다

**① 결정적 동작 준수는 게이트로 남는다.** 요청된 형식, 필수 용어, 스키마 유효성, tool call 구조,
종료 사유, 잘림, 요구된 섹션 수. 판정자가 필요 없다.

**② 출력 분량 패리티는 코호트 통계 모니터가 된다.** "품질"이라 부르지 않는다 — 짧은 것이 나을
수도 있다. 같은 측정 창 안에서 프록시와 direct에 같은 요청을 보내고, 표면·모델·출력 상한·지원되는
샘플링 제어를 고정한 뒤, 가시 문자 수와 출력 토큰을 **따로** 재고, 페어 로그 길이 비의 기하평균과
신뢰구간을 보고한다. 표면과 과제 계열로 층화한다. 거절·잘림·tool call·형식 실패의 처리는
**미리 선언**하고 제외 건수를 모두 보고한다.

> **A/A 대조는 필수다.** direct 요청의 약 20%를 자기 자신과 반복해 vendor 고유 변동을 잰다.
> vendor 대 vendor 분산이 측정하려는 효과만큼 크면 **그 축은 판정 불가로 보고한다.**
> 2026-08-28 시점에 관찰된 격차(claude +203자, codex −150자 내외)는 이 대조 없이 얻은 값이며,
> 아직 신호로 확정된 바 없다.

릴리스 코호트는 vendor당 24개에서 시작해 60개를 상한으로 순차 표집하고, 신뢰구간이 결정적이 되면
멈춘다. 비가 `0.90–1.10` 밖이면 **경보**를 낸다. A/A 증거가 그 대역을 분해할 수 있음을 보인 뒤에야
게이트가 된다.

**③ LLM 판정은 비게이트 진단으로만 남는다.** 이미 탐지된 코호트 변화를 조사할 때 쓰고, 입력·judge
모델·원본 출력·루브릭을 저장한다. **그 판정은 호환성 상태를 바꾸거나 기대값을 자동으로 고칠 수
없다.** 판정자를 게이트에 둔 것이 46줄을 만든 유인이었다.

## 6. 게이트

한 덩어리의 빨강/초록으로 뭉개지 않는다.

**커밋 게이트가 실패하는 조건:** 매니페스트가 유효하지 않거나 claim 전개가 비었거나 커버리지가
줄었다 / 지원한다고 선언한 표면·엔드포인트에 생성된 claim이 없다 / 필수 결정적 claim이 채택된
계약과 어긋난다 / **호출자 프롬프트 내용이 CLI 경계 이전에 추가·삭제·중복·재배열·재작성됐다** /
스트리밍 원본에 표면별 종결자가 없거나 EOF에 제대로 도달하지 않는다 / 응답 보정 재생 결과가
예기치 않게 바뀌었다 / 잘못된 요청이 수용되거나 틀린 와이어 거동으로 거절되거나 프록시가 거절해야
할 때 CLI까지 도달했다 / **네거티브 컨트롤이 이름 붙은 단언을 통해 실패하지 않았다**.

지원한다고 선언한 표면은 vendor가 문서화한 엔드포인트를 **필수로** 만든다. 현재의 404는 공표
지원 범위가 그 엔드포인트를 명시적으로 제외하지 않는 한 실제 실패로 남는다. "케이스가 없었다"는
면제가 아니다.

**의도된 발산**은 계약에 정확한 동작이 선언되고, 사용자 문서가 그 선언에서 생성되거나 연결되고,
실제 동작이 선언과 정확히 일치할 때만 통과한다. 제3의 동작은 실패다. **예기치 않게 vendor와
일치하게 된 것도 실패다** — 발산이든 그 문서든 낡았고, 조용히 수용하면 고쳐진 결함을 숨기고 다음
회귀를 통과시킨다.

**라이브 vendor 결과는 따로 분류한다.** 첫 불일치는 upstream 드리프트 후보 / 반복되는 안정적
불일치는 확정 드리프트 / 확정된 고위험 드리프트는 심의 전까지 릴리스 증거를 낡은 것으로 만든다 /
불안정하거나 부족한 관찰은 미검증이며 결코 통과가 아니다 / vendor 인증·전송·기록기 실패는 그
작업을 무효화할 뿐 프록시를 고발하지 않는다.

**미상과 불안정 건수는 증거 부채다.** 이행 중에는 래칫으로 다룬다 — 늘어날 수 없고, 고위험 미상은
완전 호환 주장을 막는다. 기대되는 통과로 바꾸지 않는다.

**초록이 나올 때까지 재실행하는 것은 허용하지 않는다.** 재시도는 기록되고 안정성 분류에 반영된다.

## 7. 이행 — 끝나기 전에 쓸모 있게

1. **먼저 증거를 잃지 않는다.** ✅ 2026-08-29 완료 — `scripts/lib/capture-recorder.mjs`가 러너의 모든
   HTTP 교환을 `artifacts/api-captures/<runId>/`에 남긴다(요청 본문 원본, 상태, 응답 헤더·바이트,
   스트림의 파싱 이전 와이어, 인증 헤더는 존재만). 단언은 이 기록을 읽지 않는다. 첫 실행이 곧바로
   `/v1/chat/completions` 스트림 종결자 `data: [DONE]`를 잡았다 — 매트릭스 최고 위험 셀이었다.
   아직 CLI 자식 프로세스의 argv·stdin·stdout은 기록하지 않는다(4단계 기록 CLI의 몫).
2. **권위를 세운다.** 148개 매트릭스 행을 매니페스트로 들인다. 라우트·프로토콜 인벤토리를 더해
   미검사 표면·없는 엔드포인트·스트림 종결자가 열거된 주장이 되게 한다. 커버리지 보고서를 내되
   미완성 주장을 아직 차단으로 만들지 않는다.
3. **수직 슬라이스 하나를 만든다.** 프롬프트 보존, 생략 시 기본값 대조 하나, 잘못된 값의 거동,
   라우트 가용성, 스트림 종결을 네 표면에서 구현한다. **저렴 티어 12호출은 2026-08-29에 실행했다**
   (`scripts/probe-direct-api.mjs`, 실패 0, 캡처는 `artifacts/direct-api-captures/`). 결과는
   `docs/conformance-matrix.md` §5.5에 있고, 첫 실행이 곧바로 프록시 발산 하나를 드러냈다 —
   `/v1/responses`에서 프록시는 `[DONE]`을 보내고 direct는 보내지 않는다. 남은 것은 **재생 경로가 그
   캡처를 실제로 소비하는 것**이다: 지금은 캡처가 쌓이기만 하고 어떤 단언도 읽지 않는다.
4. **결정적 PR 게이트를 켠다.** 기록 CLI, 응답 보정 재생, 표준 SDK 디코딩, 네거티브 컨트롤,
   커버리지 검사. 알려진 기존 실패는 **날짜 붙은 이행 원장**에 넣고 눈에 보이게 실패로 둔다 —
   계약 예외로 바꾸지 않는다.
5. **기존 shape 단언 38개를 이관한다.** 주장 단위로 옮기고, 각각에 대해 관련 원본 캡처나 어댑터
   동작을 **변이시켜 새 게이트가 실패하는 것을 본 뒤** 옛 단언을 지운다.
6. **증거를 채운다.** 전체 티어(53 호출)를 돌리되 생략 시 기본값 셀과 불안정한 관찰 9건을
   우선한다. 뒷받침되는 관찰만 승격한다. 미상은 미상으로 남긴다.
7. **품질 실험을 교체한다.** 페어 코호트 모니터를 최소 두 개의 독립 코호트에서 그림자 모드로
   돌린다. **A/A 잡음 바닥을 먼저 재고** 나서 릴리스 게이트를 켠다.

`docs/api-benchmark-design.md`와 3,870줄 러너는 **마지막에** 은퇴한다 — latency와 image 커버리지가
아직 거기 산다.

## 8. 이 설계의 위험

1. **고정된 캡처가 화석화된 vendor 계약이 된다.** 탐지: 예약된 저렴 티어 프로브, provider
   핑거프린트, 증거 신선도 보고, 확정 드리프트 심의. **새 캡처를 자동 승격하지 않는다.**
2. **matcher나 정규화가 거짓 초록을 만든다.** 탐지: 상태·헤더·프롬프트 span·이벤트 순서·종결자·
   EOF·응답 필드에 이름 붙은 네거티브 컨트롤. **모든 matcher는 실제 분기에 도달하는 변이로
   증명되어야 하고**, 의도한 단언을 통해 실패해야 한다.
3. **분량 모니터가 잡음이거나 또 다른 최적화 표적이 된다.** 탐지: vendor A/A 분산, 보정 대
   홀드아웃 계열 결과, 제외율 보고, 신뢰구간 폭. **잡음 바닥이 측정된 격차를 분해하지 못하면
   게이트를 끄고 그 지표가 결정을 뒷받침할 수 없다고 보고한다.**

## 출처

이 설계는 2026-08-28에 두 개의 독립 초안을 합쳐 확정했다. 하나는 이 레포에서 작성됐고, 다른
하나는 같은 블라인드 패킷(증거·제약·요구 항목만, 결론 없음)을 다른 provider의 프론티어 모델
(`gpt-5.6-sol`, xhigh effort)에 보내 받았다. 두 초안이 독립적으로 수렴한 항목 — 권위는 데이터·
러너는 코드, LLM 판정의 게이트 강등, 원본 바이트 보존, 낡은 발산도 실패, 세 레인 분리 — 은
신뢰도가 높은 것으로 본다. claim 단위, 프롬프트 보존 게이트, 기록 CLI 레인, A/A 대조, 회전하는
생성 프롬프트, 캡처 승격 심의는 외부 초안에서 왔다.
